# LSPosed 与 Root 控制面板

安装 Android ARM64 APK 后，在兼容 libxposed API 102 的 LSPosed 中启用模块，推荐作用域为 `system`。按管理器提示重启手机，然后在 App 内检查框架与 Root 状态，校验并安装载荷。

LSPosed 在 `system_server` 激活模块入口。Root 控制器把相机载荷加载到独立的 `cameraserver` 进程，载荷通过 Camera3 输出缓冲区替换画面。控制器核对进程映射和与当前 PID 一致的就绪标记后才报告 hook 就绪。普通 App 无需单独加入作用域。

- 全局摄像头和照片功能分别开关，共用同一个视频来源。照片替换处理 Camera2 JPEG 输出，保留原 JPEG 的像素尺寸和 EXIF 方向。输出需要缩放时按照片比例居中裁剪，清晰度仍取决于输入画面。Pixel 5 的 Google 相机 HDR+ 可用 RAW10 在应用内合成照片，该路径使用原生传感器数据。
- Pixel 5 的 Android 14 录像编码器默认请求高通 UBWC 缓冲区。开启全局相机后重新打开录像模式，模块在创建这种录像输出流时协商线性 YUV 缓冲区，供实际编码的 MP4 使用。
- 关闭相机和照片开关后，停止供帧并恢复原生画面。相机载荷留在当前进程待命，重新开启可复用。使用“停止全部并恢复系统服务”彻底卸载。
- 虚拟麦克风默认关闭。需要替换时手动选择音频输入，再开启麦克风开关。开启后，已接管的录音路径在等待音频或缓冲区无效时输出静音。关闭后使用手机原生麦克风。
- OBS 和 RTMP 服务运行在电脑。面板保存可从手机访问的电脑 RTMP 地址，开启相机、照片或已选 OBS AAC 的虚拟麦克风后开始拉流。旧手机接收配置升级后需重新填写地址，已导入的本地媒体可继续使用。 [电脑与手机配置](../README.md#obs-与画面分辨率)
- 面板退出后控制器管理的运行状态仍可能处于开启。结束时使用“停止全部并恢复系统服务”，检查结果提示。

状态中的开关、feeder、hook 和媒体通道分别表示用户选择、进程就绪、系统接入和媒体发布。面板分别显示 OBS 拉流进程、已解码的媒体通道，以及录像编码队列接收的替换帧。录像计数表示系统队列已接收，保存文件需要由相机客户端完成。

新版载荷安装到 Root 所有的受保护目录 `/data/cr/payload`。更新时会识别旧路径下已经运行的 feeder 并停止它。此前选择的媒体仍可读取，新导入的文件写入 `/data/cr/media`。

打开相机后回到面板刷新，可以查看当前 `cameraserver` 的直接提交和取景缓冲记录。Android 14 上的 Pixel 5 会用 `PreviewFrameSpacer` 调度 Google 相机的 `PRIVATE` 取景流，同时直接提交 `YUV_420_888` 和 `RAW10`。取景缓冲接收数记录已替换帧进入待显示队列的次数，画面由相机客户端随后渲染。RAW10 保留原始传感器数据，照片开关只处理带有效 JPEG 尾标的 Camera3 BLOB。

开发签名 APK 由 CI 生成，正式发布需使用稳定签名。旧桌面产物由对应历史版本维护。模块涉及系统服务，固件适配请在授权设备验证。
