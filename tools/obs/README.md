# OBS 自动管理 MediaMTX

用 Windows x64 的 OBS 启动和管理中继。已验证 OBS 33.0.1 与 MediaMTX 1.21.4。MediaMTX 转发 OBS 已编码的音视频。手机可继续使用已安装的 LONG Virtual Camera APK。

## 首次加载

1. 下载本目录的 [longvc-mediamtx.lua](longvc-mediamtx.lua) 和 [mediamtx-obs.yml](mediamtx-obs.yml)，放到同一目录。
2. 在 OBS「工具 → 脚本」点「+」，选择 `longvc-mediamtx.lua`。在脚本里选择已经解压的 `mediamtx.exe`，或把该程序放在脚本旁边。 [OBS 脚本](https://docs.obsproject.com/scripting) · [MediaMTX 安装](https://mediamtx.org/docs/kickoff/install)
3. OBS「设置 → 直播」选择「自定义」，服务器可用 `rtmp://127.0.0.1:1935/longvc`，推流码留空，关闭身份验证，视频选择 H.264。已有本机 RTMP 地址时，在脚本勾选「沿用 OBS 本机推流地址」。脚本在启动和应用设置时识别回环地址或本机网卡的局域网 IPv4，并读取端口与流路径。也可手动填写端口和流路径，OBS 推流到 `127.0.0.1`。 [OBS 发布设置](https://mediamtx.org/docs/publish/obs-studio)
4. 点击「启动 / 应用中继设置」，在「脚本日志」确认“中继已就绪”。如果已有中继占用端口，脚本会等待。停流并退出旧实例后，脚本会接手该端口。确认中继就绪后开始推流。

「随 OBS 自动启动中继」默认开启。OBS 会为当前场景集合加载脚本，并在退出或卸载脚本时关闭它创建的中继。子进程启动成功后异常退出时，脚本会尝试重启。相同设置可重复应用，变更运行中的中继设置需要先停止 OBS 推流。

## 手机拉流

| 连接 | 操作 | 手机上的拉流地址 |
| --- | --- | --- |
| USB | OBS 推流到 `127.0.0.1`，电脑运行 `adb reverse tcp:1935 tcp:1935` | `rtmp://127.0.0.1:1935/longvc` |
| 局域网 | 勾选「允许局域网拉流」并应用脚本设置 | `rtmp://电脑局域网IP:1935/longvc` |

「允许局域网拉流」默认关闭。升级后需要用 Wi‑Fi 的用户勾选一次即可。开启后，可访问中继的私有 IPv4 设备能读取配置的流路径，手机地址变更后也能继续拉流。电脑仍是唯一允许发布的来源。沿用 OBS 的本机网卡地址时，中继绑定该地址。RTMP 为明文，请在可信网络开启局域网拉流。

## 手机画面构图

在 OBS「工具 → 脚本」加载 [longvc-camera-framing.lua](longvc-camera-framing.lua)（OBS 30.1 起）。在「来源」选中一张照片或一个视频，再选「照片 4:3 / 3:4」或「录像 16:9 / 9:16」，点击「完整适配所选来源」。该操作会恢复场景项的完整画面，保留镜像和旋转，并使画面落在手机居中裁切后仍可见的区域。要回到应用前的位置和裁剪，可点「恢复上一次构图」。

Pixel 5 默认照片路径为 4:3，常用录像为 16:9。专用照片场景可把「基础画布」和「输出分辨率」同时设为 `1440×1080`，竖图可用 `1080×1440`。以录像为主的场景可同时设为 `1920×1080` 或 `1080×1920`。已在用 `1920×1080` 输出时，可以继续保留它，用照片模式把主体放进中间约 `1440×1080` 的区域。源比例与拍摄比例不同时会留边，适合完整展示照片。手机相机数字变焦以及来源自身的裁剪滤镜会进一步影响取景。

## 排查

- **中继就绪，手机等待帧**。确认 OBS 已开始推流、视频使用 H.264、手机拉流地址和端口正确。
- **检查实际推流状态**。点击「检查中继和推流状态」，在「脚本日志」查看中继是否监听、OBS 是否在推流或重连，以及两边的端口与流路径是否匹配。正在推流时会同时显示 OBS 输出分辨率和累计网络丢帧。
- **端口被占用**。在脚本日志查看端口，检查是否另有 MediaMTX 实例，或为脚本使用其他空闲端口。
- **更换场景集合后停流**。OBS 将脚本保存在场景集合中。需要使用中继的集合应加载此脚本。
